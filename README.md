# 🚒 消防団・現場支援水利アプリ v13（40人同時利用を想定したテスト版）

## 今回の方針

- 出欠アプリとは完全に別アプリ
- Supabaseは使用しない
- GitHub Pages：画面・地図・操作
- Google Apps Script：共有データの読み書き
- Googleスプレッドシート：水利・現場データ
- 同時利用は約40人を想定
- 実際に書き込むのは多くても約20人を想定
- 多くは同じ現場情報を閲覧・共有

## 水利の対象範囲

最大で以下だけを扱います。

- 南蒲田3丁目
- 西糀谷1〜4丁目
- 北糀谷
- 上記の管轄境界から外側200m

東京全域の水利をアプリへ返しません。

## 40人向けの軽量化

1. 水利基本データはApps ScriptのCacheServiceに共有キャッシュ
2. キャッシュがある間はGoogleスプレッドシート全体を毎回読みません
3. 火災地点から200m以内だけを返します
4. 40人の画面操作はGitHub Pages側で処理
5. 共有状態だけ10秒ごとに自動更新
6. 「🔄 最新状態」で手動更新も可能
7. 水利状態・消防車・通行止めの書き込みにはScript Lockを使用

これにより、40人が同じ現場を見るケースでGASへの無駄な通信を抑えます。

## 初回設定

1. `gas_api_Code.gs` を水利テスト用スプレッドシートのApps Scriptへ貼る
2. `setupAll()` を1回実行
3. 東京消防庁の公式XLSXをスプレッドシートへインポート
4. シート名を `IMPORT_消火栓` と `IMPORT_防火水槽` にする
5. Apps Scriptで `refreshWaterCache()` を1回実行
6. ウェブアプリとしてデプロイ
7. WebアプリURLを `index.html` の `API_URL` に設定
8. GitHub Pagesへアップロード

## 水利更新

公式XLSXを差し替えたら、Apps Scriptの `refreshWaterCache()` を実行してください。
アプリの再デプロイは不要です。

## 共有状態

水利の状態、消防車、通行止めは現場単位で共有されます。
アプリは10秒ごとに最新状態を取得します。

## 現場終了

「現場終了」を押すと、その現場を非アクティブにします。
`Incident` / `IncidentWater` / `Markers` の記録は削除せず残します。

## 注意

この版はテスト運用向けです。GoogleスプレッドシートのGAS APIを公開する場合は、アクセス権設定を消防団の運用に合わせてください。
また、40人同時利用を想定していますが、実運用前に10人→20人→40人の負荷テストを行うことを推奨します。
